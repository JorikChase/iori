# Timeline plan — iori.me/timeline.html (2026-10-13)

A book-length, lazy, Google-Photos-like timeline of iori's life and work, from
**4.12.2003** forward, editable on the page itself when the dash account is
logged in, minimal in light and dark.

Decisions taken on 2026-10-13 (iori):

| Fork | Decision |
|---|---|
| The `.readme` memoir | Import as **private drafts**: 11 places become chapters, the prose becomes private entries; iori publishes each one from edit mode. Nothing public until published. Entries naming third parties get a flag in the editor. |
| Editor host | **On iori.me/timeline.html?edit**, authenticated against api.3die.fr with the dash account. |
| Typeface | Not fixed: a **dropdown in the settings** (Manrope / Jost / Outfit to start). |
| Media source | **Uploads from the dash/editor**, date from EXIF when present. No Takeout import, no bulk import of existing pages. |

Assumptions stated here, change if wrong:
- The font dropdown is an **author** setting (what every visitor sees). Visitors get only the
  light/dark toggle. Desktop decides where a decision cannot differ per view.
- Oldest first, page opens at 4.12.2003. "Open at today" is a settings flip, not a rebuild.
- The raw `.readme` never enters git or the webroot (already gitignored and rsync-excluded).

## 1. Shape

```
timeline.html                 the page (registered in pages.meta.json, iori.me, category essay)
timeline/
  timeline.css                tokens, light/dark, type, frames, rail, scrubber, editor chrome
  timeline.js                 boot: index → layout → virtual scroll → chunk loader → kinds
  kinds/                      one renderer per entry kind (image, video, audio, text, link,
                              embed, page, module, mention, chapter)
  editor.js                   lazy-imported only on ?edit after /auth/me succeeds
  snippets/<slug>.js|.jpg     ES-module snippets (shader / three.js) + their posters
  data/                       GENERATED by the API publish step — never hand-edited
    index.json                settings + one compact row per public entry
    <yyyy>.json               full public entries for a year
    e/<slug>.json             unlisted entries, reachable by link only
    m/<slug>.html             tiny OG stub per public entry (phase 4)
tools/timeline/
  import_readme.py            local-only seed: .readme → chapters + private drafts via the API
  mentions.json / mentions.py curated external mentions + a checker (status, title, first seen)
```

The page is static. The API is only touched in edit mode. Visitors load
`index.json` (≈ 40 bytes/entry → 5,000 entries ≈ 200 KB gzip ~60 KB), then year chunks as
they scroll.

## 2. Data model (API, SQLite table `timeline`)

| field | type | notes |
|---|---|---|
| id | int | |
| slug | text unique | `2007-03-first-music`; share anchor; stable once published |
| date | text | ISO `YYYY-MM-DD` |
| precision | text | `day` / `month` / `year` / `none` (undated draft) |
| date_end | text null | spans (a place lived, a job) |
| kind | text | image video audio text link embed page module mention chapter |
| title | text | |
| body | text | Markdown subset: paragraphs, emphasis, links, lists |
| media | json | `[{name, w, h, dur?, poster?}]` — thumbnails at 480/1080/2160 WebP (new in API) |
| src | text null | embed URL / page URL / snippet slug / mention URL |
| frame | json | `{w: 1/3 \| 1/2 \| 2/3 \| 1 \| bleed, a: aspect, align: l\|c\|r}` |
| chapter | text null | slug of the chapter entry it belongs to |
| tags | json | |
| visibility | text | `public` / `unlisted` / `private` |
| flags | json | `["names-people"]` set by the importer, cleared by iori |
| position | int | order inside the same day |
| created_at / updated_at / published_at | text | |

Settings doc (`timeline_settings`, one row): `font` (manrope \| jost \| outfit), `order`
(asc \| desc), `start` (origin \| now), `theme` (system \| light \| dark), `origin` fixed
`2003-12-04`. Mirrored into `index.json` so the page needs no API call.

Index row: `[slug, date, precision, kind, aspect, frameW, chapter?]`.

## 3. API additions (`api/main.py`)

- `GET  /timeline` (admin: all; public: none — the public reads static files)
- `POST /timeline`, `PATCH /timeline/{id}`, `DELETE /timeline/{id}` — admin only
- `PUT  /timeline/{id}/media` multipart; EXIF date read with Pillow; thumbnails written next
  to the original under `/media/t/`
- `POST /timeline/unfurl` `{url}` → `{title, site, favicon, image}` stored on link cards
- `POST /timeline/poster/{slug}` — the editor uploads a captured canvas frame for a snippet
- `PUT  /timeline/settings`
- `POST /timeline/publish` — writes `timeline/data/*` into the webroot (atomic: tmp dir →
  rename). Only `public` rows reach `index.json`/year files; `unlisted` rows go to `e/`;
  `private` rows never leave the DB.
- Auth: `get_session_user` also accepts `Authorization: Bearer <token>`; `/auth/login`
  returns the token in the body as well as the cookie. The page stores it in localStorage
  **only on iori.me after an explicit edit-mode login**; logout deletes it. This is what
  makes `?edit` work in Safari, which drops the cross-site cookie.
- `CORS_ORIGINS` += `https://iori.me`, plus the local preview origin.

## 4. Rendering

- **Virtual scroll.** Layout is computed for every row from the index alone (aspect + frame
  width → height), so the scrollbar is right from the first paint. About 60 entries are in
  the DOM at a time; the rest are empty space.
- **Chunk loading.** A year file is fetched when its first row is within two viewports.
  Thumbnails use `srcset`; videos `preload=none` with a poster; audio shows a waveform
  poster and plays inline.
- **WebGL budget.** `module` and `page` kinds show their poster until within one viewport,
  then mount; at most **2 live contexts**; the farthest is destroyed first. `page` kinds are
  `<iframe>`s of existing iori.me pages, created only when live.
- **Module contract** (`timeline/snippets/<slug>.js`):
  ```js
  export default {
    aspect: 16 / 9,
    mount(el, { theme, reducedMotion, signal }) { /* own canvas inside el */ return { resize(), destroy() } }
  }
  ```
- **Day groups.** Consecutive `image` entries on one day with `frame.w ≤ 1/2` collapse into
  one justified row (Google Photos). Any entry with `frame.w ≥ 2/3` breaks the row.
- **Rail and scrubber.** Wide screens: a sticky year → month rail on the left (replaces the
  paper's contents rail). All screens: a thin right-edge scrubber with year ticks; drag jumps
  years, like the Photos scrubber. Current year/month in the rail updates from the scroll.
- **Chapters.** Full-width quiet headers (place name, span, one line), listed in the rail.

## 5. Look

- Reading column from `papers/fractals/paper.css`: 40rem text, 54rem figures; `bleed`
  frames go to the viewport width minus the gutter. Phone: one column, 16px gutter, no
  horizontal scroll.
- Type: one geometric family (the setting), 17px/1.65 body, dates in small tabular
  figures along the rail. Links: underline with offset in prose; external links as quiet
  cards (favicon, title, domain) with no shadow.
- Tokens on `:root`, redefined under `prefers-color-scheme: dark` and `[data-theme]`.
  Light: white paper, hairline frames. Dark: near-black, no frames, photos undimmed.
  A manual toggle in the corner, remembered per viewer.
- Edit chrome never changes the reading layout: frame handles appear on hover/selection,
  a bottom toolbar holds add / settings / publish / undated-drafts.

## 6. Editor (`?edit`)

- Boot: `GET /auth/me` (cookie or stored bearer). Not admin → the page renders exactly as
  for a visitor plus a small login sheet. Admin → `editor.js` loads.
- Add: a `+` between any two entries and in the toolbar. Kinds in a short menu. Drop a file
  anywhere → image/video/audio entry at the EXIF date (or the date under the cursor).
- Frame: drag the corner → width snaps to 1/3, 1/2, 2/3, 1, bleed; aspect from the media,
  or dragged for text/embeds. Drag the handle to reorder inside a day.
- Fields in a side sheet: date + precision, title, body, visibility, chapter, tags, src.
  Flagged entries (names people) show the flag until cleared.
- Undated drafts live in a tray (the imported prose arrives here without dates); dragging
  one onto the timeline sets its date.
- Settings sheet: font dropdown (live preview), order, start, theme default. Publish
  button → `/timeline/publish` → the static data refreshes; the page re-reads the index.

- `tools/timeline/import_readme.py` (run locally, never deployed): parses the `N] Place`
  markers into 11 `chapter` entries (chapter 1 at 2003-12-04, the rest undated), each block
  of prose into a `text` entry, `visibility=private`, flag `names-people` where a capitalised
  given name appears outside the first line. Idempotent by a content hash.
- Mentions found 2026-10-13 (all institutional, no press): Czech trade registry (IČO
  19748809, trade from 2023-09-20), LinkedIn (Flashtones, from 2023-05), AVU student page
  (Nová média 1), GitHub `JorikChase/iori`, the YouTube channel, 3die.fr, the portfolio
  page. Search Console has no backlinks API, so `tools/timeline/mentions.json` is curated
  and `mentions.py` only re-checks (HTTP status, title, first seen) and prints a diff.
  Each becomes a `mention` entry by hand in the editor.

Deploy notes (as built in P1): the API service may only write its own folders, so published
data lives in **/var/www/timeline-data** (`TIMELINE_DIR`, in the service's ReadWritePaths) and Caddy
serves it at `iori.me/timeline/data/*` with `no-cache`. It is outside the webroot, so a deploy never
wipes it and no rsync exclude is needed. Upload originals go to `/var/lib/iori-api/originals`
(`ORIGINALS_DIR`, never served); thumbnails and video/audio to `/var/www/media/t/` (3die.fr/media,
immutable). `.readme` stays gitignored and excluded.
