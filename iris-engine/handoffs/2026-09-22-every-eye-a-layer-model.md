## 1. Where the project stands, in one paragraph

Visitors to iori.me meet one of **four layer-model eyes** (09, 25, 26, 35), chosen per visit, loaded from shipped
measurements in ≈ 0.3 s on this Mac and ≈ 2.5–3.3 s over the network (8.5 s on a first, uncached visit to the largest,
09) — no photograph, no 5 MB case file. **Engine 0.9.5-yellow** moved the spectral LUT's yellow-pigment edge from 500 to
450 nm: the old edge left every blue violet (the legacy lavender cast) and eye 09's cyan-blue out of gamut. The page
saves its whole state as a session file (⌘/Ctrl + S), keeps it between visits, and the Tissue window has a **Paint page
with a guide brush** whose strokes survive reloads (the op journal lives in the session). **Next is G1b**: parent
splines that drive their strands, with Actualize to edit each strand (iori's design, study/11 §5.1).

## 3. Run it, test it, deploy it

```bash
python3 iris-engine/serve.py 8769            # or launch config "iris-engine-8769"; http://localhost:8769/iris-engine/
```
Tests and benches open the page with **`?start=off`** (no start eye, no kept session read or written). Gates:
```js
await import('/iris-engine/tools/ui-contract/contract.js');
await __uiContract.reach();                                   // []
__uiContract.start({ iters: 20 }); /* stage 'done' */ await __uiContract.compare();   // []
await __irisEngine.fit.benchIsolated({ iters: 120, save: false });   // 67.1 / 66.8 / 69.4 / 66.8 since 0.9.5
```
**Always `save: false`** — `save: true` rewrites `ref/cases.json` (the legacy fits the presets and casebook read).
Re-export an eye's shipped file whenever the engine version or a default dial changes (the key refuses a stale file,
so a stale file costs speed, never correctness): a measured load at NORMAL, then
`IrisTissue.exportMeasurements({ lightBits: 10, shadeBits: 11 })` → `POST /save/data/tissue-NN.cal.bin`.
Deploy (iori asks; always the script from origin/main):
```bash
ssh iori-vps 'cd /root/iori && git -c http.version=HTTP/1.1 fetch -q origin && git show origin/main:server_setup.sh > /tmp/server_setup.sh && bash /tmp/server_setup.sh'
```
`*.bin` is under the no-cache app-code rule since this stretch.

## 5. What this stretch learned, and what it cost to learn

- **The published 84.6 for eye 26 was drift.** `importID`, seeds and presets wrote `state.ringR` without `target.ringR`;
  the render loop eased every eye's ring back to 0.4, on screen and during staged loads. Fixed; the eye as fitted is
  84.24. Any SMOOTH_KEY written without its target is this bug again.
- **The light cannot be coarsened.** At the pupil margin it falls 1 → 0 within a pixel and toAlbedo divides by it:
  any interpolation moves the ruff (step 2: 8 / 255, step 4: 20 / 255).
- **Measure before calling a defect.** Twice I read a review sheet wrong by eye ("35 is squashed" — its tissue really is
  348 × 307 px; "the pupils are too big" — the dark-disc radii match). The black photo background against the renders'
  white fools the eye.
- **The blue was out of gamut, not mis-graded.** A 3 × 3 camera matrix "fixed" it only by tinting grey cyan; a white-
  preserving one recovered nothing. The yellow edge was the lever, and the per-photo hue rotations had been
  compensating for it all along (grades ≈ identity at 450 nm). The grade objective was a plain mean without the sheet:
  a 9 % blue was invisible to it.
- **A model change moves more than the bench.** 0.9.5 left the legacy presets lavender (fitted to the old LUT) until
  re-baked, and would have made the Load button drift from the shipped eye had it kept reading `ref/cases.json` — both
  paths now read the pinned `data/case-NN.json`.
- **The legacy fitter loses ~1 point on 25 / 26 under 0.9.5 — not the gamut** (the engine LUT reaches both better,
  `engine_gamut.py`): its fitted eye is too green in the gaps between fibres, with gap constants tuned to the old LUT
  (`gapStromaMul` 0.35, `gapMelMul` 1.2). For the production rebuild.
- **A hidden browser tab delivers no animation frames.** The load's last wait now gives up after 1 s (a visitor's
  background tab would otherwise have hung "loading"); long benches are slowed by timer throttling in a hidden pane.
- **An `add` op must snapshot its curve.** Later ops mutate the curve in the set; a journal that stored the reference
  would replay the edits twice. Fixed before G1b needs it.

## 6. Open, named honestly

- **The measured load is path-dependent** (study/11 §3.4): eye 26 measures 84.245 or 84.627 depending on which load path
  a page runs *first*, and that holds for the rest of the page (max 14 / 255). Only the de-light tile maps differ
  (992 421 vs 992 601 pixels). Ruled out: case contents, smoothed-state drift, timing, yielding between stages,
  `E.state` at the measurement, stray texture bindings, the margin uniforms, the deck-height cache, the live map.
  Visitors never measure; the Load button can show a picture up to 14 / 255 off the shipped one. Next: bisect `X.load`
  line by line in a fresh page.
- **The iPad and phone timings after S3** are not measured (Help ▸ Load timing, iori's devices).
- **Fitting on the site (T8)**: the fitter takes 5–10 CPU min and **2.9–4.1 GB** peak per eye — a phone tab dies near
  1 GB; T8 needs a leaner pipeline, not a straight port.
- **The production rebuild** (study/11 §3.4) waits for G2 (furrows as primitives, so the layer eyes stop borrowing
  legacy relief from the cases) and S4 (the compact format); then one reproducible script, ending in review sheets.
- **09's blue** is much better (its excess error over the texture floor 7.3 → 3.0) but still a shade less saturated than
  the photograph's cyan.
